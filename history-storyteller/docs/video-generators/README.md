# Image-to-video generators — options

The pipeline needs one **image-to-video** clip per scene, animated from the approved Xiaohei still. **Grok Imagine** (the built-in GenerateVideo tool) is the current default. The alternatives run on the box's signed-in Chrome sessions:
- **Google Flow** is worked **directly in Flow's web UI** in the box's Chrome (manual browser operation). The **gflow-cli MCP** is only a **fallback** when the browser route has a fault or no access.
- **Krea** runs through the **Krea MCP connector**, with krea.ai/video in the browser as the fallback (unchanged).
- **Step 0 for every option, before any video credits are spent (per-part workflow):** split the story into **parts 1..N**. For each part make **exactly one** matched pair — `scenes/partN_start.jpg` + `scenes/partN_end.jpg` (end generated **FROM** the start via image-to-image / edit; same background, camera, framing, scale, Xiaohei and objects; only the action's progress changes) — plus `prompts/partN.txt` (motion-only transition prompt joining start → end). Pick 2–3 refs from [`../../reference-images/`](../../reference-images/) per part, match style, check the pair side by side, regenerate drift. **Never** generate independent stills of every frame or unrelated images per beat. Show **part 1** (start + end + prompt) for approval; after approval produce **part by part** (check pair → generate clip with start + end + prompt → verify → next). Krea start-only models: start + prompt; end frame is the check target. All sketches and clips are **vertical 9:16** (never 16:9); always pass aspect `"9:16"` explicitly and verify height > width.
- **Grok Imagine per-part chain (default generator):** each part ≤8 s is **two 4 s clips chained** (start-frame only). Clip A from `partN_start.jpg` → extract A's last frame → clip B from that frame continuing to the end state; `partN_end.jpg` is the **check target only**. Join A+B into one continuous one-way 8 s take (no loop/zoom). **Never** animate the two sketches as unrelated clips (jump at 4 s). Test at **480p** → QA the join → **upscale locally to 720×1280** with Real-ESRGAN (`realesr-animevideov3`); do **not** regenerate at 720p (different motion). Scripts: [`../../scripts/video/chain_and_upscale.sh`](../../scripts/video/chain_and_upscale.sh), standalone upscale [`../../scripts/video/upscale_720p.sh`](../../scripts/video/upscale_720p.sh) + [`../upscale-real-esrgan.md`](../upscale-real-esrgan.md). Details: [grok-imagine.md](grok-imagine.md).
- **Flow clip length hard limit:** a Flow/Veo start→end clip is at most **8 s** (durations 4 / 6 / 8 only). When planning parts, each part's narration slot must be **≤ 8 s** (~18–20 English words; rewrite/split, never stretch audio); if a beat is longer, split it into two parts and make the next part's start frame match the previous end frame for continuity. Choose 4, 6 or 8 s to cover the slot; RIFE retimes afterwards.
- **Total length & approval summary:** propose **~50 s – ~1.5 min** per story (about **7–11 parts**). The approval table's up-front line states `This script = N parts / N clips, ~T s. Flow estimate: N × ~10 ≈ C credits (Veo 3.1 Lite).` Part count = clip count = number of start+end sketch pairs.
- **Route failures:**
  - **Flow (browser-primary):** if the browser route has a fault or no access, fall back to the gflow-cli MCP (tell the user). Do not start with MCP when the browser works.
  - **Krea (MCP-primary):** if the MCP route doesn't work (connector or server error, auth failure, missing tool, repeated failures), the bot **offers the user a choice** to switch to manual browser operation, using the web UI steps in the Krea doc. It goes to the browser only after the user picks it.
  - A credit shortage (402 / `insufficient_balance` / no profile with credits) is not a route failure: stop and tell the user, with no buying.
- **Hugging Face** is run directly in the browser by the bot's browser/desktop agent. Its MCP route is only a secondary note.

## Same rules after any generator
1. One-direction, progressive motion **per part** (`partN_start` → `partN_end` + `prompts/partN.txt`). No loop, ping-pong, reverse, freeze, zoom or pan (camera locked in the prompt). Flow: ≤8 s per part. **Grok:** two×4 s chained clips (see [grok-imagine.md](grok-imagine.md)); upscale approved 480p with [`../upscale-real-esrgan.md`](../upscale-real-esrgan.md) instead of regenerating 720p.
2. RIFE 4.7 motion-equalized retime to the scene slot at true 24 fps (`../../scripts/video/rife_eq.py`), then jolt fixes. Never interpolate across a cut.
3. Layout into 1080x1920 with `../../scripts/video/build.py` (crop to art, scale, English title/underline/subtitles/counter) — see **Frame layout (mandatory)** in each generator doc; sketches are illustration-only (`no text, no letters, no captions`), large Xiaohei filling most of the width; approval samples via `../../scripts/video/preview_frame.py`.
4. QA סרטונים check before delivery.

## Spending rules (all options)
- Never buy credits, plans or subscriptions unless the user explicitly asks.
- Don't generate before the user has approved the script and the sample frame.
- Check the balance first. If it isn't enough, stop and tell the user.
